# Data Model: Eval Comparison Chart

Feature: `/specs/004-eval-comparison-chart/spec.md` · Date: 2026-10-04

This feature introduces **no persistence change** and **no artifact schema change**. It derives three read-only view entities from the existing `EvalResults` / `ModeAggregate` / `CaseResult` contracts in `src/data/evalResults.ts` (unchanged, generated by `npm run eval:chain`). All entities below are computed at render time inside `EvalComparison.vue`.

## Entities

### EvalMetric

A switchable chart metric. Static definition list (module constant in `EvalComparison.vue`), not persisted.

| Field | Type | Notes |
|---|---|---|
| `key` | keyof `ModeAggregate` | One of the six percentage fields: `retrievalHitRate`, `injectionCoverRate`, `factRecall`, `faithfulness`, `actionPassRate`, `chainPassRate`. |
| `label` | `string` | Human label for the chip + bar sub-label (e.g. `hit@K`, `injection cover`, `fact recall`, `faithfulness`, `action pass`, `chain pass`). |
| `color` | `string` | CSS color-variant class name (e.g. `--amber` / `--orange` alternation) used for the bar fill and chip accent. |

**Rules**: `meanTotalLatencyMs` (ms, not a percentage) and `hallucinationRate` (a defect rate) are excluded — the chart scale is uniform 0–100%. Default active set = `retrievalHitRate` + `faithfulness`.

### CompareRow

One method's chart row (computed per active metric set).

| Field | Type | Notes |
|---|---|---|
| `mode` | `string` | Mode name from `ModeAggregate.mode` (`lexical`/`vector`/`hybrid`/`decide`). |
| `bars` | `CompareBar[]` | One bar per **active** `EvalMetric`, in metric definition order. |

`CompareBar = { key: EvalMetric['key'], label: string, value: number (0–1), pct: string }`.

### QuestionGroup

One fixture's grouped view (computed from `evalResults.cases`).

| Field | Type | Notes |
|---|---|---|
| `fixtureIndex` | `number` | Grouping key (`CaseResult.fixtureIndex`). |
| `query` | `string` | The fixture query (rendered once per group). |
| `rows` | `ModeCaseRow[]` | One row per mode that ran this fixture. |

`ModeCaseRow = CaseResult` (full existing shape) — PASS/FAIL marker via `chainPass`, fact-recall/faithfulness bars via `score.factRecall`/`score.faithfulness`, meta via `mode`/`effectiveMode`/`injectedNames`/`appliedTheme`, reason via `caseReason(entry)`.

## Relationships

- `EvalMetric` → `CompareRow.bars` (active metrics only) → `ModeAggregate` fields (read-only).
- `QuestionGroup` → `ModeCaseRow[]` (`CaseResult` reuses the existing `score`/`timings`/pass flags untouched).
- Both views are pure functions of `evalResults` (prop): `evalResults.modes` → chart rows; `evalResults.cases` (grouped by `fixtureIndex`, original order) → question groups.

## Validation rules

- At least one `EvalMetric` is always active: deselecting the last active chip is a no-op (guard in the toggle handler).
- Group order = order of first appearance of `fixtureIndex` in `evalResults.cases`; row order within a group = mode order in `evalResults.config.modes`.
- Empty artifact (`evalResults.fixtures === 0` or no modes): `EvalComparison.vue` renders nothing; the existing empty-state note in `BlogPostPage.vue` stays.
- A mode row with `effectiveMode !== mode` renders the meta as `mode → effectiveMode` (unchanged semantics).
