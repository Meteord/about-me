# Implementation Plan: Eval Comparison Chart

**Branch**: `004-eval-comparison-chart` | **Date**: 2026-10-04 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/004-eval-comparison-chart/spec.md`

## Summary

The "Chat with my website" blog post's eval section gains a **single comparison bar chart** plotting every retrieval mode (`lexical`/`vector`/`hybrid`/`decide`) against a switchable percentage metric, plus a **question-by-question** grouped result list. A multi-select pixel-chip switch (default: hit@K + faithfulness) picks which metrics the chart plots; each active metric renders one horizontal bar per mode using the existing pixel-bar primitives (`tool-result__bar`, `barClip`, `pct`) — no chart library (research R-1). Below the chart, `evalResults.cases` are grouped by `fixtureIndex` with one row per mode (PASS/FAIL, injected/action meta, reason, fact-recall + faithfulness bars) so methods are compared per question (R-3). New state lives in a dedicated `EvalComparison.vue` component (R-4); CSS is added to `src/assets/main.css` under `eval-chart*`/`eval-compare*` names (R-5). The artifact schema, eval scripts, and fixtures are **unchanged** — the committed artifact may hold 1..N modes and the section renders it honestly (R-6); a full 4-mode comparison is a `npm run eval:chain` regeneration step, documented in the quickstart.

## Technical Context

**Language/Version**: TypeScript 5.8 on Vue 3 (`<script setup lang="ts">`), Vite (`rolldown-vite`). Eval scripts unchanged (ESM `.mjs`).

**Primary Dependencies**: No new runtime dependencies. Reuses `src/data/evalResults.ts` (types `EvalResults`/`ModeAggregate`/`CaseResult`), the existing pixel-bar CSS primitives, and the `pct()`/`barClip()`/`caseReason()` helpers (moved into `EvalComparison.vue`).

**Storage**: Static only. `evalResults.ts` is the sole data source, read-only. No persistence or schema changes; the artifact is regenerated by `npm run eval:chain` (unchanged).

**Testing**: No test suite (constitution Principle III). Gates: `npm run lint` → `npm run build` from `frontend/`. `npm run eval:retrieval` MUST still pass (no eval changes).

**Target Platform**: Static SPA on GitHub Pages at `/about-me/` (client-side only).

**Project Type**: Web application (frontend-only).

**Performance Goals**: Pure client-side rendering of ≤4 mode rows × ≤6 metric bars + ≤140 grouped rows; no network, no measurable cost. No impact on load (no new imports beyond the existing component graph).

**Constraints**: No backend/secrets; `vite.config.ts` base stays `/about-me/`; all styles global in `src/assets/main.css` (`eval-chart*`/`eval-compare*` naming), no `<style>` blocks; no new routes/`SectionId`s; accessibility preserved (`aria-pressed` chips, `aria-expanded`/`aria-controls` toggle, `:focus-visible`, `prefers-reduced-motion`, ≤480px); artifact schema and eval scripts unchanged.

**Scale/Scope**: 1 new component (`EvalComparison.vue`), 1 modified component (`BlogPostPage.vue`), CSS additions/removals in `src/assets/main.css`. No changes to eval scripts, fixtures, registry, or llms content.
