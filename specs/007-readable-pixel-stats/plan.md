# Implementation Plan: Readable Pixel Page with Animated Statistics

**Branch**: `007-readable-pixel-stats` | **Date**: 2026-11-13 | **Spec**: [`specs/007-readable-pixel-stats/spec.md`](./spec.md)

**Input**: Feature specification from `/specs/007-readable-pixel-stats/spec.md`

## Summary

Replace the two-column, collapsible "pixel-window" desktop with a single editorial scroll: the introduction, then an animated statistics band, then the on-device showcase, then About details, Blog, Projects and Contact — all permanently open, with no visitor-facing collapse control. The assistant moves out of the left dock into a dedicated inline section plus a compact home-page launcher that share exactly one conversation and one model session. All advanced chat detail (mode chips, scores, candidate lists, checkpoint names, trace export) collapses behind one explicit `details` affordance, and the showcase speaks in plain language by default.

Every statistic is derived at build time from already-shipped data — `src/data/siteData.ts`, the committed `src/data/evalResults.ts` artifact, `src/tools/registry.ts` and the Vite build year — never hand-entered; a statistic whose source cannot be read is dropped, and an empty band does not render. Motion is one shared system: an `IntersectionObserver`-driven reveal plus a stepped count-up that runs at most once per element, finishes in under 1.5 s, and is fully bypassed (final values immediately, nothing hidden) under `prefers-reduced-motion` or when the observer/animejs module is unavailable.

The pixel identity is simplified, not removed: notched 8px frames, warm dark palette, hard offset shadows and `steps()` easing stay; the three chrome squares, the `−`/`+` toggles, per-window marquee stripes and display-face headings outside the site name/section titles go. Because the spec removes visitor-facing collapse and the constitution currently mandates collapsible sections plus `aria-controls`/`aria-expanded` on section toggles, this plan carries an explicit constitution amendment (Principles II and V) — see Constitution Check and Complexity Tracking.

## Technical Context

**Language/Version**: TypeScript ~5.8 (`vue-tsc` 3.0), Vue 3.5 single-file components with `<script setup lang="ts">`, Node.js `^20.19.0 || >=22.12.0` for the Vite and evaluation scripts

**Primary Dependencies**: Vue 3, Vite (`rolldown-vite`), `animejs` ^4.5 (already a dependency; lazily imported for stepped motion), `@huggingface/transformers` ^4.2 for the unchanged on-device chat/retrieval models. No new dependencies.

**Storage**: Static, committed TypeScript data only — `src/data/siteData.ts` (person/content facts), `src/data/evalResults.ts` (committed evaluation artifact, regenerated by `npm run eval:chain`), `public/llms/*.md` (retrieval content). No browser persistence, no cookies, no telemetry.

**Testing**: `npm run lint` → `npm run build` (runs `vue-tsc --build` + `vite build`) from `frontend/`, plus `npm run eval:retrieval` (must report zero missed held-out test cases) and `npm run eval:chain -- --modes=bm25` when the shared modules it imports are touched. No unit-test suite exists; visual, keyboard, reduced-motion and responsive verification is a manual matrix defined in `quickstart.md`.

**Target Platform**: Static GitHub Pages SPA (base `/about-me/`), evergreen desktop and mobile browsers; WebGPU-first with WASM fallback for the on-device models, rendered entirely client-side.

**Project Type**: Single-page web application (`frontend/`) with Node ESM scripts (`frontend/scripts/`) that generate content and evaluation artifacts.

**Performance Goals**: All content readable with zero animation dependency; reveal completes in ≤ 300 ms and count-up in ≤ 1.2 s (budget 1.5 s); no animation-caused layout shift (values are tabular and box-width-stable); no new network requests, model downloads unchanged; scrolling stays fluid on low-powered devices (motion is limited to opacity/transform and one rAF counter per visible card).

**Constraints**: Client-only, no backend/keys/telemetry/live instrumentation (Constitution I; spec FR-026); remain a router-free single page (Constitution II); global styling only in `src/assets/main.css` with `--pixel-*`/`--font-*` variables, notched `clip-path` corners, `border-radius` ≤ 2px, hard offset shadows, `steps()` easing (Constitution IV, spec FR-003); 60–75 character measure, 12 px type floor, 4.5:1 contrast in all three accent themes (spec FR-002/FR-013/FR-014, SC-002/SC-006); reduced-motion and keyboard support (Constitution V, spec FR-009/FR-010); retrieval source names and aliases unchanged so the committed evaluation stays valid without re-tuning (spec FR-022); GitHub Pages base path untouched.

**Scale/Scope**: One home composition (7 bands: intro, stats, showcase, about details, blog, projects, contact) plus the two hash-routed views (blog article, projects page); 3 career + 4 engineering statistics, each individually omittable, in 2 groups; ~11 new `src/` modules, ~12 modified files, and a CSS layer of roughly 3.4k lines to refactor rather than extend.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **I. Client-Only & On-Device (NON-NEGOTIABLE)**: **PASS** — No backend, key, tracking or telemetry is added. Statistics are computed from already-shipped static data at build time; the chat model, retrieval models and their disposal lifecycle are unchanged in behaviour (only re-hosted in shared UI).
- **II. Static Single-Page Simplicity**: **PASS with required amendment** — Still a router-free Vue 3 SPA in `frontend/`, with the existing hash-routed blog article and projects page and no new dependencies. However, the principle says new views MUST be *collapsible* pixel-window sections, while spec FR-001/FR-021 removes visitor-facing collapse. This is an intentional, spec-mandated redefinition and MUST be amended (MINOR) before implementation, replacing "collapsible sections" with "always-open pixel-window sections, assistant-hideable".
- **III. Verify Before Ship (NON-NEGOTIABLE)**: **PASS** — The plan keeps `npm run lint` → `npm run build` as the gate and requires `npm run eval:retrieval` to stay green (zero missed test fixtures). `quickstart.md` adds a manual visual/keyboard/reduced-motion matrix since no test suite exists.
- **IV. Pixel-Theme Fidelity**: **PASS** — All styling stays in `src/assets/main.css` using `--pixel-*`/`--font-*` variables, notched corners, hard offset shadows, `steps()` easing, no `<style>` blocks. The feature *reduces* ornament (chrome squares, toggles, marquee stripes, extra borders) without relaxing any rule; a small, documented palette/overlay reduction is recorded in `research.md` (scanline opacity) rather than bypassing the rule.
- **V. Accessibility & Motion Safety**: **PASS with required amendment** — `:focus-visible`, `prefers-reduced-motion`, `text-wrap: pretty` and the 480 px breakpoint are preserved, and the plan adds accessible disclosure (`aria-expanded`/`aria-controls` on the details toggle), a focus-trapped launcher dialog with Escape/return focus, and a screen-reader-visible final statistic value. The principle currently mandates `aria-controls` + `aria-expanded` on *section toggles*; since section headers become static headings, that clause MUST be amended (MINOR) to require those attributes on any *remaining* disclosure control (details toggle, launcher) instead.
- **VI. Retrieval-Ready Content**: **PASS** — `SOURCE_DEFS` names, aliases and section mappings are unchanged, so retrieval and the committed evaluation remain valid (spec FR-022). No new content source is added; the statistics band is presentation over content that is already retrievable (education, skills, blog, project, evaluation explanation). If page copy in `public/llms/*.md` needs to mention the band, `npm run generate:llms` regenerates it and `eval:retrieval` must still pass.

*Post-Phase 1 Design Re-check*: All six principles hold under the two documented amendments (II and V). No other violations; Complexity Tracking contains only the amendment justification.

## Complexity Tracking

> Constitution Check violations that must be justified and resolved by amendment.

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|--------------------------------------|
| Principle II ("new views MUST be collapsible pixel-window sections") | Spec FR-001/FR-021 and all P1 user stories require every section readable with zero clicks and forbid any visitor-facing collapse or expand control. | Keeping collapsible sections contradicts the feature's core request ("easier to read, less clunky") and its measured success criterion SC-001; hiding the substance behind toggles is the primary defect being fixed. Amendment keeps "no routes" and the pixel-window section model intact. |
| Principle V ("`aria-controls` + `aria-expanded` on section toggles") | With static section headers there is no toggle to describe; the remaining disclosure controls (technical-details toggle, floating launcher) carry `aria-expanded`/`aria-controls`, and the launcher dialog adds Escape/focus-return. | Keeping a decorative, non-functional toggle to satisfy the letter of the rule would violate spec FR-004 (no ornament that implies an action it does not perform) and confuse keyboard/screen-reader users. Amendment moves the requirement to real disclosure controls. |
